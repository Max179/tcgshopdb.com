# tcgshopdb.com

A source-only static site for the game **TCG Card Shop Simulator**, published at <https://tcgshopdb.com>.
Pages are generated by a small Node builder from a normalized data index that is committed to this repository.
There is no framework, database or runtime service: the deploy target is a folder of HTML, CSS, SVG and image
files.

The output has two deliberately separate layers:

- **Player layer** — home, game guide, entity hub and 11 player category pages, entity pages, 63 guides, tools
  and updates. These are the pages a player is meant to find.
- **Evidence layer** — class, field, enum and value tables plus provenance, under `/reference/` and
  `/entity/` and marked `noindex`. These pages exist so a claim can be checked, not to rank in search.

This tree is the 2026-10-02 Windows handoff package with the Mac design integration ported back onto it. The
records for both are in `reports/`; the revival pass is `reports/revival-2026-10-30.md` and the integration
plan it followed is `reports/mac-integration-plan.md`.

## Requirements

- **Node.js 22+** (the publish workflow uses Node 22). Build, tests and gates need no third-party packages.
- **Python 3** with Pillow only for optional image tooling (`tools/image-sanity.py`), not for the build.
- No access to the game, no credentials and no network are needed to build or test the committed tree.

## Preview

```sh
npm run build
python3 -m http.server 4205 --directory web/dist
# open http://127.0.0.1:4205/
```

`npm run build` writes `web/dist/`, which is generated output and is not tracked by git.

## Commands

| Command | What it does |
| --- | --- |
| `npm run build` | Regenerate `web/dist/` from the committed data and content. The build prints `pages=445 indexable=176`. |
| `npm test` | Run the 80 site gates (`tests/site.test.mjs`). Builds into a temp directory and checks routes, clean canonical URLs, the SEO contract (titles, descriptions, og/twitter, JSON-LD, sitemap lastmod, robots, IndexNow key), noindex/sitemap policy, provenance, images (including the picture-source ledger and the generated credit table), content invariants, duplicate indexable pages, mobile viewport and the publish configuration. |
| `npm run typecheck` | `tsc --noEmit -p tsconfig.ci.json` — portable type roots, checks the `.mjs` pipeline and tests. |
| `npm run gates` | Content gate, coverage matrix, image coverage and citation check, in that order. |
| `npm run classify` | Rewrite `config/urls.json` (one keep/noindex line per emitted page, keyed by its clean public URL) from `web/dist` + sitemap. |
| `npm run indexnow` | Submit the built sitemap to IndexNow (Bing/Yandex). Manual publish step with network access; never run by the build, tests or deploy workflow. |
| `npm run image-sanity` | Flag near-uniform or near-blank mapped images (Python 3 + Pillow) into `reports/image-sanity.md`. |
| `npm run preflight` | Publish checklist: runs the site gates, requires a clean working tree, checks `reports/status.json`, the handoff report, the workflow, the raw/build boundaries and the coverage floor. |
| `npm run smoke` | Check the built artefact against the classified URL list. With a URL argument (`npm run smoke -- https://tcgshopdb.com`) it checks the live site instead. |
| `npm run status` | Recompute `reports/status.json` from a fresh temp build plus git. |
| `npm run deploy-check` | Local readiness vs external blockers (git remote, Cloudflare secrets). |
| `npm run verify` | `npm test && npm run typecheck && npm run preflight` — the full local gate chain. It expects a clean tree, so run it after committing. |

Typecheck (TypeScript is a devDependency; covers `.mjs`):

```sh
npm install
npm run typecheck
```

`node_modules/` is ignored and must not be committed. The build and tests do not need it.

## Data boundary

- **Raw game files are not in git.** `data/raw/` is ignored; nothing under it is tracked. The repository ships
  only the normalized index, so a clean clone can build, test and gate the site without the game.
- **Regenerating the data requires Windows.** The extractors read a local TCG Card Shop Simulator install
  (Unity 6 `Card Shop Simulator_Data`, `Managed/Assembly-CSharp.dll`, level/shared asset files) and the
  extraction scripts contain hard-coded Windows paths for that host. They also need Python with UnityPy for the
  Unity object table, while the value decoder is the repository's own .NET/ECMA-335 metadata reader.
- **Therefore the normalized data is not reproducible on a clean Mac clone.** The committed indexes are the build
  input; re-extraction is a separate, host-specific step.
- **Decoded instances are mostly engine-side objects.** The 260 decoded objects in
  `data/normalized/p0-instances.json` are what the value decoder could fully consume and are mostly
  UnityEngine-side types; they are not card price tables. Player-facing facts in `content/published/` come from
  localization tables, assembly scans and the game's own named assets, each with an evidence pointer checked by
  `tools/verify-citations.mjs`. A card value the build could not read is not printed and is not estimated; the
  site never invents card values or prices.
- **No game bytes are committed.** The intermediate payload dumps (`data/normalized/*-payloads.json`) are
  ignored, and the raw package is excluded from the deploy artefact.

## Images and licensing

The MIT licence in [`LICENSE`](LICENSE) covers the **site code only**. It does not relicense any picture:

- **Game pictures** are in-game pictures: screenshots from the game's official Steam store page, files from its
  community wiki (the TCG Card Shop Simulator Wiki on wiki.gg; earlier passes used the TCG Card Shop Wiki on
  Fandom where that wiki had a file), and pictures taken from the game itself. They belong to the game's developer
  and their rights holders, and to the wiki uploaders for community files. They are used only to identify the
  subject an entry describes, under a fair-use review, and this site does not relicense them. Every file is
  recorded in `content/images-manifest.json` with its kind, entity, source name, source page (an absolute URL),
  the original image URL where the source publishes one, licence and rights-review status, retrieval date and
  hash, and every record carries a reviewed verdict in `reports/image-reviews.md`. The build generates the
  per-file credit table on `/reference/sources.html#pictures` from that manifest, and every published page
  carries the same "Picture taken from the game to identify this item" label next to its picture.
- **Original diagrams** were drawn for this site and are labelled as diagrams, never as screenshots.

The build's content gate refuses a published entry without an image, a diagram presented as a screenshot, or an
image without English and Chinese alt text. The site tests refuse a picture record that does not carry a source
name, a source page, a retrieval date and a rights review, a source page that is not an absolute `http(s)` URL,
or a record that the generated credit table does not list.

## SEO and URL scheme

Pages are stored as `.html` files but the host serves them at **clean URLs** (`/entries/cards`, `/entities/`,
`/`) and 308-redirects the `.html` forms. Everything a crawler reads uses the clean form, so no link or
canonical points at a redirect: canonical, `og:url`, hreflang, the sitemap, JSON-LD and every internal link.

- **Titles** are generated per page: the page's own subject plus the brand suffix, and the suffix is dropped rather
  than exceeding 60 characters. Every indexable page has a unique 25-60 character title.
- **Descriptions** are unique and 70-160 characters, cut on a word boundary (never mid-word).
- **JSON-LD**: the home page carries `WebSite` + `SearchAction`; every indexable page carries a `WebPage` (or
  `Article` for entries and guides) plus a `BreadcrumbList`, all with URLs matching the canonical.
- **Social**: `og:title/description/url/image/type` and `twitter:card/title/description/image` on every
  indexable page; the twitter image is the og image.
- **Sitemap**: exactly the 176 indexable pages in clean URL form. `<lastmod>` is only written where content
  metadata supplies a truthful date (an `updates.json` date, or the picture record date of a pictured entry);
  undated pages carry no `lastmod` rather than a faked build date.
- **robots.txt**: `Allow: /` plus the sitemap line, with the `noindex` policy for the reference/evidence layer.
- **IndexNow**: `web/indexnow-key.txt` is a public 32-hex ownership key; the build serves it at
  `/<key>.txt` from the dist root. `tools/indexnow.mjs` is the manual submission step and is not part of the
  build or the deploy workflow.

## Deploy

In short: `.github/workflows/publish.yml` runs the gates and then deploys `web/dist` to the Cloudflare Pages
project `tcgshopdb-com` on a push to `main`.

- CI gate job: build → site tests → typecheck.
- Deploy job (after the gate): build → `tools/preflight.mjs` → `tools/smoke.mjs` → `wrangler pages deploy`.
- DNS and custom-domain changes are dashboard actions, not part of the workflow.

The deployment history, current status and the local evidence are in `reports/local-complete.md` and
`reports/status.json`.

## Secrets

The repository contains **no credentials, tokens or private keys**. Deployment uses the
`CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` GitHub repository secrets, which are injected at deploy time
and never written to a tracked file. Do not commit a token, an account ID or a local `.env`; `preflight` checks
that the workflow uses a secret rather than a literal token.
