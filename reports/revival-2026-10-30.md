## 3. Design integration

The package deliberately ships the **Windows copy** of the shared shell: its `style.css` hard-codes the sibling
site's red accent (`--accent:#ff5c5c`) while `SITE.accent` says `#8b7cff`, and the handoff itself says the shell
is design-owned by the Mac commits. The design was ported **onto** the package generator, not the reverse:

- SITE block: Mac tagline (`Build a card shop: open packs, price singles, stock shelves and make the next sale`),
  the Mac teal palette from 8c1312f (`#8fe3cf` accent, `#111619` background, `#203b39` radial highlight,
  `#1b2928` panels), and the verified in-game homepage imagery from 6169d5e
  (`web/assets/hero-shop.jpg` = the furniture texture, `web/assets/featured-card.jpg` = the fire card front;
  both files are also mapped in `content/images-manifest.json`, so their origin is re-checkable).
- `layout()`: sticky header with the letter mark, the five-section player nav, header search, the wide player
  column, and the footer with the source line and the policy links.
- Home page: the Mac hero (eyebrow, game name, lead, search, three player CTAs, picture card with caption), a
  split "what this game is / card front" section, then the package's approved player modules (popular entities,
  player-question guide cards, updates, provenance note).
- `style.css`, `brand.svg` and `favicon.svg` are emitted from the single `SITE.accent` value, in the Mac visual
  system; the package's player/evidence markup (cards, chips, entry page, facts panel, banners, tables) is styled in
  the same system so all 445 pages render, not just the home page.
- `web/assets` is published under `/assets/` as the Mac design referenced it; `content/assets` stays at the root
  (`mapped/...`) as the content files reference it.
- Renders: `reports/redesign-p0/mac-integration-before-home.png` (thin shell, 257/13 build),
  `...-after-home.png` (integrated build), `...-after-entry.png`, `...-after-home-mobile.png` (430×932).

## 4. macOS cleanliness and SEO/snippet fixes

- No Windows path is read at build, test, gate or typecheck time. Windows paths remain only in extraction-only
  scripts (`pipeline/*.ts` decoders, written for the extraction host) and in provenance data/reports, which the
  build reads as strings at most. `tsconfig.json` typeRoots are portable.
- LF everywhere (two package files were CRLF and were normalized); `.gitattributes` `* text=auto eol=lf`.
- Typecheck works with the documented `tsconfig.ci.json` and with plain `tsconfig.json` on macOS.
- Meta descriptions are capped at 160 characters (sibling site's `metaDescription` convention); before this the
  category pages emitted up to 694-character descriptions. Note pages now render their own summary paragraph so the
  page carries the text its gates look for.

## 7. Remaining blockers and residual items

- **Live deploy is the Lead's leg.** This pass did not push or deploy. The Lead fixed the Cloudflare secrets and
  reported the deploy path working; after the push, run
  `node tools/smoke.mjs https://tcgshopdb.com` (the post-publish mode of `tools/smoke.mjs`).
- **New extraction needs the Windows host.** The normalized data cannot be regenerated on this Mac; the committed
  indexes are the build input. The 260 decoded instances are mostly engine-side objects, so card values that were
  not verified are still absent on the site (explicit unknown, never invented). This is the documented data
  boundary, not a build blocker.
- **JSON-LD schema is not emitted yet.** The factory's standard asks for VideoGame/Article/BreadcrumbList/FAQPage
  structured data. The Oct-2 package predates that requirement and the gates do not cover it; it is the next site
  improvement (recorded here so it is not mistaken for done).
- **Sitemap has no `lastmod`** (the sibling site added it in a later round).
- **AdSense is not enabled** (deliberately): about/contact/privacy/terms/disclaimer exist, content is original,
  images are attributed, and no ad code is in the build — the account decision stays with the owner.
- **`reports/mac-handoff-manifest.json` is the package receipt**, generated on Windows. It describes the package
  as handed over, not this repository after the design port; treat it as historical evidence, not as a checksum
  manifest of the current tree.
- The package's `image-sanity.md` said 2 flagged; the macOS run flags 12 (Pillow/measurement difference). The
  review ledger covers all 186 records and the site gate that requires a verdict for every flagged file passes.
